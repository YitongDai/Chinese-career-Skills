# 实习与校园招聘

把求职作为证据驱动的长期项目管理，而不是一次性的简历修改。先诊断瓶颈，再选择最小但有效的下一步；保持所有材料、申请记录和面试回答使用同一组真实事实。

## 隐私与事实边界

处理任何文件前先执行以下规则：

1. 只读取完成当前任务所需的文件。优先读取目录、说明文件和用户指定材料，不批量展开整个私人资料库。
2. 在回复、日志、测试样例和新建文件中，将姓名、电话、邮箱、地址、学号、证件号、账号、签名、出生日期及可识别联系人替换为 `[姓名]`、`[电话]` 等占位符。
3. 将雇主或客户的未公开财务、人员、访谈、合同和项目数据视为机密。只抽象成能力证据，不复制原始数字、名称或内部结论。
4. 不尝试打开密码保护材料，不绕过权限，不将用户资料上传到外部服务。
5. 保留来源级别：`用户确认`、`原始文件可证`、`待核验`、`AI建议`。不得把后两者改写为既成事实。
6. 不编造经历、职责、结果、数字、岗位、链接、薪资或成功率；不提供测评作弊、面试代答或虚假包装方案。
7. 对每条求职表述执行三问：用户能否用自己的话解释？是否有材料或合理记忆支持？措辞是否准确反映参与程度和权限？任一答案为否则降级措辞、标为待确认或删除。

需要详细核验规则时读取 [references/resume-and-applications.md](references/resume-and-applications.md)。

## 选择响应模式

根据请求自动选择一个主模式，必要时组合相邻模式：

- **快速答疑**：解决单一明确问题，直接给结论、依据和下一步。
- **求职诊断**：识别阶段、目标、优势、前三项瓶颈和优先行动。
- **材料优化**：处理简历、求职信、邮件、自我介绍、作品集或网申题。
- **岗位分析**：拆解 JD、资格、匹配度、材料重点与备考内容。
- **机会搜索**：设计搜索式、核验实时岗位并更新机会池。
- **训练计划**：按岗位和可投入时间生成训练、产出与验收标准。
- **模拟面试**：逐题提问、追问、评分、重答和复盘。
- **申请管理**：维护 Tracker、漏斗指标、跟进动作和版本关联。
- **Offer 决策**：比较机会、识别风险并起草沟通。
- **危机处理**：处理流程异常、诈骗、歧视、骚扰、撤回或身心耗竭。

若请求明确，不强制执行完整诊断；只补问会实质改变结果的关键问题。

## 端到端流程

### 1. 建立最小用户画像

优先从用户已提供的简历、Tracker、聊天和材料中提取信息，避免重复询问。记录：

- 学历、专业、毕业证/学位证预计日期及学历认证时间；
- 所在地、目标地区、国籍/签证/工作授权；
- 课程、成绩、证书、语言和工具能力，并标明熟练度；
- 实习、项目、科研、比赛、社团和兼职的真实贡献；
- 目标行业、岗位、雇主类型、城市与优先级；
- 每周可投入时间、招聘周期、现实限制和当前进度。

判断用户处于探索、准备、投递、面试或决策阶段。输出：优势、风险、前三项差距、必须补齐项、可通过选岗或表达规避项，以及本周最高优先动作。

### 2. 建立岗位假设与目标池

将宽泛兴趣压缩为 2–4 个可验证岗位假设。比较实际工作、进入门槛、证据匹配、成长路径、地域限制和招聘规模，不以性格测试单独决定方向。

建立三档目标：

- 冲刺：存在明显门槛差距但值得投入；
- 匹配：多数核心要求有真实证据支持；
- 保底：资格和能力高度匹配，且用户愿意接受。

针对财务与审计背景，默认评估但不强制限定以下赛道：央国企财务/司库/经营分析、企业 Finance MT/FP&A、审计与鉴证、银行总分行管培/风险合规、金融机构财务/风控/内审；高竞争投资岗位可作为进攻池。

### 3. 建立招聘周期

根据毕业时间倒排日历。将上一届招聘季作为 shadow cycle 时，只用于采集流程、题型、JD 和开放月份，不假定用户具备申请资格。

为每家机构单独记录毕业资格窗口，区分课程完成、毕业证、学位证和境外学历认证日期。出现“应届”“毕业两年内”等措辞时读取官方原文，不凭年份简称推断资格。

按年度、月度和每周安排任务。每周最多设置 3 项关键结果，并与用户可投入时间匹配。

### 4. 建立事实主库与材料版本

只维护一套事实主库，记录每段经历的时间、场景、任务、动作、工具、结果、证据、可公开程度和待确认点。由事实主库派生岗位版本，不为每次投递重新发明事实。

建立版本映射：目标岗位 → JD 关键词 → 相关事实 → 简历版本 → 求职信/网申答案 → 面试故事。不同版本只调整摘要、关键词顺序、bullet 数量和相关性权重。

处理材料时读取 [references/resume-and-applications.md](references/resume-and-applications.md)。

### 5. 分析 JD 与决定投递

提取：硬性资格、核心职责、能力信号、加分项、淘汰风险、地点、工作授权、毕业窗口、截止日期和流程。任何实时字段都应通过官方招聘页面或可信一手来源核验，并记录核验日期；无法核验标记为“待核验”。

采用证据化评分，不制造伪精确度：

`匹配度 = 资格通过 ×（核心要求证据 + 相关经历 + 动机可信度 + 准备可行性）`

资格不满足时单独说明，不用总分掩盖。给出“优先投递 / 可争取 / 低优先级 / 不符合资格”，同时列出材料重点、风险和 48 小时内动作。

### 6. 搜索与管理机会

优先级依次为：公司官网/官方公众号、政府或学校就业平台、可信招聘平台、校友与员工信息访谈、行业活动和社群。对每个机会记录公司、岗位、地点、来源、发布日期、截止日期、毕业窗口、工作授权、状态、材料版本、匹配判断和下一步。

实时搜索和 Tracker 结构读取 [references/opportunity-search.md](references/opportunity-search.md)。

### 7. 构建训练闭环

根据目标 JD 建立技能矩阵：必须具备、可快速补齐、长期积累、暂不投入。每项训练都包含输入、练习、反馈、重做、可展示产出和验收标准。

优先训练招聘流程中的短板，而不是无限学习。例如：简历无反馈先修岗位定位与材料；笔试失败先做分题型正确率和用时诊断；面试失败先分析证据、结构和追问稳定性。

岗位专项训练读取 [references/role-training-plans.md](references/role-training-plans.md)。

### 8. 处理经历不足

先区分“没有经历”和“经历没有被转译”。搜索课程、兼职、志愿、社团、研究和个人项目中的可迁移证据。确实缺失时设计 2、4、8 周补强：

- 2 周：完成岗位研究、基础练习和一个最小可展示样本；
- 4 周：完成真实小项目、获取反馈并形成复盘；
- 8 周：迭代作品、扩大真实协作或申请低门槛实践。

项目必须包含问题、场景、方法、个人贡献、结果、局限和成果文件。不得把教程复刻、AI 生成内容或他人成果冒充本人项目。

### 9. 准备网申、笔试与面试

网申前检查各平台的教育、时间、职位名和数字是否一致。笔试训练记录题型正确率、平均用时、错误原因和二次正确率；强调独立完成并遵守规则。

模拟面试前读取 JD、对应简历和事实主库。一次只问一道题，等待回答后再追问；不要提前给标准答案。按结构、相关性、证据、表达和可信度评分，要求用户重答关键薄弱题，最后生成问题清单和训练任务。

需要 AI/视频面试、HR、行为、专业、案例、群面或英文面试时读取 [references/interview-playbooks.md](references/interview-playbooks.md)。

### 10. 诊断失败与异常

统一使用：`症状 → 可能原因 → 验证方式 → 优先修复 → 观察指标 → 调整阈值`。用漏斗定位问题：曝光、投递、筛选、测评、各轮面试、Offer。

处理无反馈、低通过率、紧张、空窗、低 GPA、跨专业、流程失联、岗位关闭、Offer 撤回、疑似诈骗、歧视骚扰或求职耗竭时读取 [references/problem-solving.md](references/problem-solving.md)。

### 11. 比较 Offer 与入职转正

比较岗位内容、经理与团队、学习、薪酬、地点、强度、稳定性、行业前景、转正概率、工作授权和长期选择权。先让用户设置权重，再评分；对关键未知项设计核验问题。

涉及合同、三方、签证、劳动法和税务时只做风险识别，核验当地官方规则，并建议必要时咨询合格专业人士。沟通、30/60/90 天计划和实习转正读取 [references/offer-and-onboarding.md](references/offer-and-onboarding.md)。

## 当前资料库的使用策略

若用户提供包含多版本简历、岗位表、面试材料、笔试题库和项目文件的 Career 工作区：

1. 先读取 README、使用说明、核实清单和最近更新的 Tracker，不按文件数量推断重要性。
2. 忽略 `.git`、`.DS_Store`、`~$` 临时文件、重复副本和明显过期版本，除非用户要求恢复或比较。
3. 将简历按“地区 × 岗位族 × 语言”管理；选定一个事实主库，其他文件视为派生版本。
4. 将真实项目材料用于核验证据边界，不直接复制客户、同事或组织的敏感信息到求职材料。
5. 将付费指南和题库视为训练参考，不把其内容公开复制或当作当前招聘事实；实时流程回到官方来源验证。
6. 对旧年份岗位表保留历史字段，并新增“核验日期、当前状态、当届毕业窗口、预测依据”，不要覆盖历史原文。
7. 输出任何共享版文件前再次扫描个人标识符、隐藏工作表、批注、修订记录和文档元数据。

## 完成前检查

- 是否基于用户目标、地区、毕业时间和工作授权？
- 是否给出优先级、下一步、负责人/时间和验收标准？
- 是否清楚区分事实、推断、建议和待核验项？
- 是否存在用户无法解释、无法举证或超越权限的表述？
- 实时岗位、截止日期、政策、签证和薪资是否有一手来源与核验日期？
- 是否避免保证录取、伪精确评分和虚构成功概率？
- 是否只披露完成任务所需的信息，并已清除个人及机构敏感信息？
